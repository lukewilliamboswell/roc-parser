# roc-parser 2.1.0

2.1.0 adds tooling that works on source text: two new modules, `RocSyntax` for Roc source and `AsciiDoc` for AsciiDoc documents, and source-preserving tokens for YAML. Every addition is new API. No public signature changed, and existing functions return the same results on every input.

## Upgrade impact

- **Requires Roc nightly `nightly-2026-10-18-1df370f`.** Earlier nightlies don't build this release. Upgrade the compiler before you upgrade the package.
- The `unicode` dependency is now [4.3.0](https://github.com/roc-lang/unicode/releases/tag/4.3.0). On 10-18, earlier versions print compiler warnings.
- `CSV`, `HTTP`, `Markdown`, `Parser`, `Utf8` and `Xml` are unchanged from 2.0.0. `Yaml` only gains the source-highlighting functions below.

## New features

### `RocSyntax`

`RocSyntax` parses Roc source into source-backed tokens, a tolerant indexed syntax tree and located diagnostics. It is meant for highlighters and source-analysis tools.

- The tree represents expressions, patterns, type declarations, constraints and every header form.
- Parsing has explicit nesting and token limits. It does not do binding or type analysis.
- Malformed input gets partial structure, and its tokens can still be highlighted.
- `tokenize_str`, `tokenize_bytes` and `highlight_category` serve lexical highlighting without building a tree.

Legacy Rust compiler syntax is outside its scope. See the manual's "Parsing Roc source" chapter.

On the development machine, every input in the reference performance comparison parses within 1.5 times the time of the compiler's own Zig parser. The syntax parsed matches compiler commit `0d4b0ab0`. That grammar is still changing, so expect follow-up releases as the language evolves.

### `AsciiDoc`

`AsciiDoc` adds block parsing, preprocessing on virtual sources, and embedded HTML rendering. It is tested against a pinned Asciidoctor on authored fixtures, independently generated models and reproducible mutations. Compatibility with Asciidoctor is not complete; see the manual's AsciiDoc chapter for what is covered.

### YAML source highlighting

`Yaml.tokenize_str` and `Yaml.tokenize_bytes` cover the original source with tokens, keeping its exact bytes. They include comments, whitespace and malformed snippets. They also report mapping-key roles, YAML 1.2 scalar categories and located diagnostics. `Yaml.highlight_category` maps tokens to theme categories that HTML and PDF renderers can share.

Semantic YAML decoding is unchanged.

## Documentation and tooling

- New manual chapters for Roc syntax, AsciiDoc and YAML source highlighting, each with tested examples.
- `scripts/check_roc_syntax.py` runs the Roc syntax feedback loop. It includes a persistent compiler reference worker, independent generated syntax, raw and structured fuzzing, an upstream snapshot corpus, and runtime, allocation and scaling checks.
- AsciiDoc and YAML source fuzz targets run in the property quality workflow.

## Release candidates

2.1.0-rc.1, rc.2 and rc.3 previewed this work on the feature branch. Changes since rc.3:

- the move to `nightly-2026-10-18-1df370f` and unicode 4.3.0;
- the Roc syntax performance work.
- `AsciiDoc.empty_item`, an internal helper exposed in the release candidates, is no longer public.
