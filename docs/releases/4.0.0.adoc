= roc-parser 4.0.0

== Upgrade impact

* *JSON writers can return `TooLarge(max_bytes)`.* Update exhaustive error
  handlers for `JsonValue.to_str` and `JsonValue.to_str_with` to handle this
  variant. Parsing and writing have no byte limit unless `max_bytes` is set.

* *`RocSyntax` spans change in two places.* A tool that stored or compared byte
  ranges may see different values; the tree's nodes and their order are the same
  for accepted source.
** A function type written inside parentheses now begins at its first argument,
   not at the opening parenthesis. In `f : (U8 -> Bool) -> U64` the inner
   `TypeFunction` is now `5..15` instead of `4..15`, which is what the compiler
   reports. The `TypeParenthesized` around it still covers both parentheses.
** In rejected source, a node that recovery stops at no longer claims a closing
   delimiter or other token it did not consume. This keeps every child inside its
   parent and stops neighbouring statements overlapping, in cases such as
   `{e:)=` and `module{`.

* *Requires a current Roc nightly and basic-cli 0.26.0.* The examples, probes and
  benchmarks use basic-cli 0.26.0, because 0.25.0 no longer compiles cleanly on
  current nightlies.
* *A top-level parser that refers to itself must be a function.* Current
  compilers reject `tree = ... Parser.lazy(|_| tree) ...` as a circular value.
  Write `tree = |{}| ...` and call `Parser.lazy(|_| tree({}))`. Parsers that refer
  to each other through one `lazy` are unaffected.
* *`RocSyntax` accepts more source, matching the compiler.* Invalid UTF-8 inside a
  comment is no longer an error, and `parse_header_str` accepts a source holding
  only whitespace and comments as the implicit header of a type module.

== Use this release

Add the package to your app's header:

[source,roc]
----
parser: "{package-url}",
----

Use a current Roc nightly. Applications using basic-cli should use 0.26.0.
The release record names the exact compiler used to build and test the package.

== Added

* `max_bytes` in `JsonValue.Options` and `JsonValue.WriteOptions` bounds input
  and output UTF-8 bytes, with an unlimited default. Input limits apply to
  runtime parsing, parser combinators and compile-time validation. The writer
  counts escaping and indentation before allocating output.

== Fixed

* `RocSyntax` reported a parenthesized function type's span with its opening
  parenthesis but not its closing one
  (https://github.com/lukewilliamboswell/roc-parser/issues/101[#101]).

== Documentation and release assets

* The manual and API reference use the shared documentation tools. The API
  archive contains unmodified compiler output; the manual is a separate PDF
  asset. GitHub Pages serves the manual and API reference together.
* The shared release workflow builds and tests the exact release candidate,
  validates the source inventory and SBOM sidecars, and publishes attestations.
  The inventory accounts for package source files and Unicode production inputs.
