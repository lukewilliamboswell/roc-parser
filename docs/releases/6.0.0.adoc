= roc-parser 6.0.0

== Upgrade impact

Use Roc `nightly-2026-11-12-ce942d6` and basic-cli 0.28.0 for the maintained
applications and examples. Repository tooling uses its separate fixed compiler.
The published release record identifies the compiler used for the delivered
package.

This major release changes AsciiDoc output where it disagreed with Asciidoctor
and adopts the compiler's current format-owned error contract. CSV and YAML
derived operations include `MissingRequiredField(Str)`, including headerless CSV
tuple parsing. Add that variant to explicitly closed result annotations that
previously allowed only `InvalidCsv(CSV.Error)`.

Existing `Xml.parse_str` and `Xml.parser` signatures and results are preserved.
The new markup APIs are additions; choose XML or HTML syntax explicitly when
switching between standalone SVG/MathML and browser markup.

== Use this release

Add the package to your app's header:

[source,roc]
----
parser: "{package-url}",
----

Applications using basic-cli should use 0.28.0.

== Added

* `Html`, `Svg` and `MathML` document and fragment parsers, with strict defaults,
  explicit HTML/XML syntax selection, configurable fragment contexts, browser
  recovery with typed diagnostics, and independent extension/value options.
* Checked literals, named imported-source validation and generic `Template(a)`
  interpolation. Fixed structure is checked during compilation; typed values
  bind to indexed text or whole quoted attribute positions without reparsing.
* Shared `Markup` trees with resolved namespaces, exact source bytes, lexical
  regions, resource limits and authored, implied or cloned node locations.
* `SvgPath` command parsing, common SVG value grammars, and MathML Core plus
  common Presentation MathML structures and child-count checks. Embedded CSS,
  JavaScript and URL languages remain outside these semantic checks.
* `Xml.reader`, with `Start`, `End` and `Text` events, subtree conversion through
  `element` and `element_with`, and document location/declaration access.
* `Xml.parse` and `Xml.ReaderProps` limits for depth, elements and attributes per
  element. Excess input fails at the relevant tag or attribute.
* `XmlNs` namespace-aware parsing and pull reading, plus `XmlNs.render` for
  namespaced trees with preserved or configured prefixes.

See the https://github.com/lukewilliamboswell/roc-parser/blob/6.0.0/docs/markup.adoc[markup guide]
for syntax differences, validation coverage, extension options and downstream
consumer examples. Runtime parsing remains pure Roc and platform-independent.

== Fixed

* AsciiDoc preserves metadata and styles on nested lists, recognises Roman
  markers, and nests differing marker styles correctly.
* AsciiDoc keeps titles on thematic breaks, handles block macros following
  verbatim styles, resolves repeated media attributes, and corrects `pass:`,
  multiline `xref:` and table-column interpretation.
* XML decodes mixed references, line endings and CDATA in linear time.

== Contributor tooling

Fuzz targets use roc-fuzz 0.6.1, and Blueprint tooling uses 0.13.0. Markup oracle
checks include pinned independent parsers, semantic validators and browser DOM
consumers. Git keeps curated cases and an upstream manifest; the full WPT corpus
is fetched and generated into ignored local storage. Markup fuzz campaigns and
benchmarks run locally, with no new scheduled campaigns.
