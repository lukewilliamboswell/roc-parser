[#releases]
= Release notes

Each release has a notes file in `docs/releases/`, written in Markdown so the
release workflow can publish it unchanged as the GitHub release description.
The notes start with the upgrade impact: every change your code or data might
notice.

* {src}/docs/releases/2.0.0.md[roc-parser 2.0.0 release notes]: a redesigned API with an upgrade guide, type-directed decoding
  of CSV and YAML into records, CommonMark and GFM Markdown, strict RFC 9112
  HTTP, XML 1.0 well-formedness, the YAML 1.2 core schema, RFC 4180 CSV, and
  property tests and conformance reviews for every format.

Earlier releases are described on the
{repo}/releases[roc-parser GitHub releases page].

== Unreleased

`RocSyntax` adds source-backed tokens and a tolerant indexed syntax tree for
highlighters and source analysis tools. It targets the pinned Zig compiler
syntax and has explicit limits on grammar coverage; legacy Rust syntax is not
supported. See <<roc-syntax>> before treating a parse result as a validity answer.

Development tooling adds a persistent compiler reference worker, independent
generated syntax checks, raw and structured fuzz targets, an upstream snapshot
corpus importer, and runtime/allocation/scaling checks. The feedback loop is
available through `scripts/check_roc_syntax.py`.
