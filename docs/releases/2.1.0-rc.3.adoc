= roc-parser 2.1.0-rc.3

This release candidate adds source-preserving YAML highlighting to the AsciiDoc and Roc syntax previews in rc.2. It is built from `feat/yaml-source-integration` (PR #92, stacked on #90) for downstream testing and requires **Roc nightly `nightly-2026-10-15-38e6c42`**.

`Yaml.tokenize_str` and `Yaml.tokenize_bytes` retain original source bytes and return a complete token partition, mapping-key roles, YAML 1.2 scalar categories and located diagnostics. `Yaml.highlight_category` provides theme categories reusable by HTML and PDF renderers. Comments, whitespace, quoting, punctuation, CRLF and Unicode keep their original byte coordinates. Block scalar scripts, quoted `+#+` and URL fragments remain scalar content; the workflow key `on` remains text.

Tokenization works on incomplete snippets and recognizes anchors, aliases, tags, directives and document markers independently of semantic decoding support. More than 256 open flow collections produces a documented lossless fallback. The semantic YAML parser's supported subset is unchanged. See the YAML manual's source-highlighting section and tested example for the API and recovery contract.

Validation includes 1,438 package tests, 20,000 optimized Linux YAML source fuzz inputs, the YAML CI smoke, generated API documentation and checks of all six packaged examples. The release includes the manual, API reference, examples pinned to this exact bundle, compiler pin, SBOM and asset checksums.

AsciiDoc compatibility remains incomplete, and the Roc syntax parser's requested 1.5-times compiler-parser performance target is still unmet. Handle diagnostics and resource limits; preview APIs may change before the final release.

On the pinned compiler, the inherited Linux `csv-decode`, `http-roundtrip` and `http-smuggling` fuzz jobs still time out. The checks remain enabled, and this preview does not establish that #90 is ready to merge. This branch preview leaves the latest stable release at *2.0.0*.
