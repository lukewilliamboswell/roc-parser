# roc-parser 2.0.0

> These notes describe the 2.0.0 release candidate on the integration branch.
> The release has not been cut yet.

2.0.0 makes every ready-made parser follow its specification. CSV, XML, HTTP,
YAML and Markdown were each compared with a mature reference implementation
and fuzzed with property tests, and most of what that turned up was fixed by
rewriting the parser rather than patching it. The public types and most
signatures are unchanged, but many inputs now parse differently: some that
used to be accepted are rejected, some that were rejected are accepted, and
some give a different result. Read the upgrade impact below before you update
the package URL.

The documentation also moved: there is now a manual alongside the API
reference.

## Upgrade impact

### Documentation site

- The versioned `www/<version>/` documentation snapshots are replaced by the
  manual and the generated API reference. Links to old `/<version>/` pages on
  the documentation site no longer work; use the manual and API reference
  links in the README instead.

### Package

- roc-parser now depends on
  [roc-lang/unicode](https://github.com/roc-lang/unicode) 4.2.0, for the
  Unicode data CommonMark needs (punctuation and whitespace categories, case
  folding). Your app downloads it with the package; no code change is needed.

### `Parser`

- `Parser.many`, `Parser.one_or_more`, `Parser.sep_by` and `Parser.sep_by1`
  stop at the first element that succeeds without consuming input, and discard
  that element's value. Before, they looped forever on parsers such as
  `many(maybe(p))` or `many(chomp_while(...))`.
- To detect progress, these four functions now require
  `where [input.is_eq : input, input -> Bool]`. `List(U8)` and every input type
  used in this package satisfy it; a custom input type must provide `is_eq`.

### `String`

- Failure messages from `codeunit`, `codeunit_satisfies`, `utf8` and `string`
  quote at most the first 32 bytes of the remaining input, followed by an
  ellipsis when truncated. Before, they quoted all of it, which made repeated
  failures quadratic. Code that matches on these message strings may need
  updating.

### `CSV`

- A final line break no longer starts an extra record: `"a\n"` is one record,
  not two. Empty input gives no records instead of `[[""]]`.
- A lone CR is accepted as a record separator, alongside LF and CRLF.
- Fields may contain any UTF-8, tabs, NUL and control characters, and a `"`
  that is not at the start of a field is an ordinary character. These were
  syntax errors.
- A blank line is a record with one empty field, as in RFC 4180's grammar.
- `CSV.u64` and `CSV.f64` use a data grammar instead of Roc literal syntax.
  `1_000`, `0x10` and `-0` are no longer U64 values, `1_0.5` and `0x1p3` are
  no longer F64 values, and F64 accepts `inf`, `infinity` and `nan` in any case, with `1e400`
  saturating to infinity instead of failing.

### `HTTP`

- Requests and responses are parsed strictly per RFC 9112 and RFC 9110. The
  body is delimited by `Content-Length` or decoded from `chunked` coding, and
  any bytes after the message are left unconsumed for the next pipelined
  message. Before, every remaining byte became the body.
- These are now rejected, to rule out request smuggling: both
  `Content-Length` and `Transfer-Encoding`; conflicting, malformed or
  overflowing `Content-Length`; any transfer coding other than a single
  `chunked`; `Transfer-Encoding` in HTTP/1.0; a missing or duplicate `Host` in
  HTTP/1.1; whitespace before a field's colon; obs-fold; bare CR or LF line
  endings; and control characters in field values.
- Status codes are exactly three digits, 100 to 999. Before, any digits were
  accepted and wrapped to `U16` (`65736` read as 200). An empty reason phrase
  is allowed.
- The HTTP version is `DIGIT "." DIGIT`, field names must be tokens, field
  values are trimmed of surrounding whitespace and may be empty, and request
  targets must be visible ASCII.

### `Xml`

- New `Xml.parse_str : Str -> Try(Xml, [XmlError(Xml.Error)])` reports a
  one-based line and byte column with each error. `Xml.xml_parser` keeps its
  signature and reports failures as `line:column: message`.
- Documents are checked for XML 1.0 well-formedness: end tags must match
  their start tags (`<a></b>` is rejected); `<` and bare `&` in attribute
  values, `]]>` and control characters in text, duplicate attributes, and
  attributes without whitespace between them are rejected.
- Names may contain digits and non-ASCII letters (`<h1>` parses).
- Entity and character references are decoded in text and attribute values
  (`&amp;` becomes `&`). Line endings and attribute values are normalised as
  the specification requires.
- Comments and processing instructions are accepted anywhere the
  specification allows and are dropped from the tree. A DOCTYPE is rejected as
  unsupported.
- Encoding names are compared case-insensitively, so `encoding="utf-8"` is now
  `Utf8Encoding` instead of `OtherEncoding("utf-8")`.

### `Yaml`

- Plain scalars resolve with the YAML 1.2 core schema. Only `null`, `Null`,
  `NULL` and `~` are null and only `true`/`True`/`TRUE` and
  `false`/`False`/`FALSE` are booleans, so `nUlL` and `tRUE` are now strings.
  `0o` octal, `0x` hexadecimal, `.inf` and `.nan` are numbers, and values such
  as `1.2.3` or `1e` are strings instead of errors.
- Literal and folded block scalars (`|`, `>`, with chomping and indentation
  indicators) are supported and follow the YAML 1.2 chomping and folding rules.
- All YAML 1.2 double-quoted escapes are supported, including `\x`, `\u` and
  `\U` code points; surrogates and values above U+10FFFF are rejected.
- Nested compact sequences (`- - x`) and sequences at their key's indentation
  (`steps:\n- a`) parse as sequences.
- Invalid YAML that used to be accepted, sometimes as a wrong value, is now
  rejected: characters outside YAML's printable set, block collections on the
  `---` line, plain scalars starting with an indicator, plain scalars
  containing `: `, and keys starting with anchors, tags or other indicators. A
  leading byte order mark is dropped.
- Quotes and brackets inside plain scalars are text (`k: it's # comment` is
  `it's`), a lone CR is a line break, and flow collections count toward the
  100-level nesting limit.

### `Markdown`

- The parser was rewritten to follow CommonMark 0.31.2 and GitHub Flavored
  Markdown (tables, task lists, strikethrough, extended autolinks), using the
  parsing strategy in the CommonMark specification. Many documents now give a
  different tree, and the new tree is the one the specification describes.
- `Markdown.all` never fails: every input is a valid CommonMark document. An
  unclosed code fence runs to the end of the document, changing the bullet
  character starts a new list, and a pipe inside a table cell's code span must
  be escaped as `\|`.
- A soft line break inside a paragraph is now kept as a `"\n"` inside `Text`:
  paragraph lines reach the inline parser joined by line feeds, as the
  specification describes.
- GFM `www.` autolinks get an `http://` prefix in the link's `href`.
- Emphasis follows the delimiter-run rules, links and images support inline,
  full, collapsed and shortcut references, and HTML5 named entities and
  numeric references are decoded.
- `Markdown.link` and `Markdown.image` keep their signatures and parse a
  leading inline link with the same engine.

## Fixes

- `Parser`: repetition over a parser that can succeed without consuming input
  no longer hangs.
- `String`: parsing with many failing alternatives is linear again (40 KB
  went from 14.5 s to 0.06 s).
- `HTTP`: a non-UTF-8 byte in a header value or request target no longer
  crashes the process.
- `Xml`: duplicate-attribute checking is linear in the number of attributes.
- `Yaml`: an unsupported escape before a multi-byte character no longer
  crashes; deeply nested flow collections are rejected quickly instead of
  running for minutes; `-   key: value` uses the column where the content
  starts.
- `Markdown`: inline parsing is linear on cmark's pathological inputs (the
  slowest went from 8.3 s to 0.05 s), block parsing is linear in the document
  size (a 64,000-line code block takes 0.05 s), only spaces and tabs are
  stripped around line endings, and whitespace is trimmed inside `<...>` link
  destinations.

## Quality and tooling

- 25 property-test targets built on
  [roc-fuzz](https://github.com/lukewilliamboswell/roc-fuzz) 0.4.2 cover every
  module: raw-input targets with metamorphic relations, structured generators
  that build the expected result from the specification, and targets that
  inject known violations (malformed XML, HTTP request smuggling). CI runs a
  smoke test of each on every pull request and a 10-minute campaign nightly.
- Conformance reviews compare each format with a pinned reference
  implementation and its test suite: Python's `csv` module, expat and the W3C
  XML Conformance Test Suite, ruamel.yaml and the yaml-test-suite, h11, and
  cmark-gfm with markdown-it-py on the CommonMark spec examples. Every allowed
  disagreement is recorded in a baseline with a reason, and CI fails on any
  other.
- A new manual covers each format, contributing, property testing and
  maintenance, and its code examples are compiled and run in CI.
