== Acceptance gate

Run `python3 scripts/check_roc_syntax_corpus.py --roc-source /path/to/roc --probe-command /path/to/probe --oracle-command /path/to/roc-syntax-oracle --output /path/to/corpus-report.json`. The workers must be freshly built from their pinned sources. The report records their executable hashes.

The gate imports the entire immutable snapshot inventory without a filter or limit. Oracle-accepted inputs require a Complete candidate parse and full consumption. Oracle-rejected inputs require candidate rejection; these include intentional errors and possibly obsolete examples, and are never treated as missing valid grammar. Worker failures, malformed protocols, source invariant failures and unhandled snapshot modes are explicit unknown failures. Every imported source and response is retained.

Accepted inputs additionally require token boundaries/classes and normalized parent/child structure to agree. Projection gaps fail as unknowns even when both workers report the same unsupported shape. Recovery trees remain implementation-specific, so invalid inputs require rejection and source invariants. The curated differential and independent-model lanes remain necessary. The report can be red while parser coverage is being expanded; unsupported source must never be relabelled as passing.

== Open production review

The finite variant inventory is accounted for. Full production/context review
remains open in the following areas and must not be inferred from one witness:

* Trivia and line boundaries around qualification, arrow/pipe receivers, call
  continuations, optional fields, and suffix operators.
* Statement dispatch and legal binding names in top-level, associated, loop,
  lambda, and ordinary block contexts.
* Record field separators, punned/default/unset fields, extension forms,
  nominal/builders, and nested container recovery.
* Nested patterns, aliases/alternatives, string captures, typed literals, and
  the distinct binding contexts which permit them.
* Type/default-expression boundaries, where clauses, function effects,
  associated definitions, and all malformed delimiter combinations.
* Header dependency validation and platform target/configuration nesting,
  including ordering, duplicates, empty strings and unusual string contents.
* Recovery locality and preservation of following declarations after edits;
  invalid-input invariants alone do not establish editor-quality recovery.

The mandatory generated-model, full upstream, editor-recovery, raw-fuzz and
oracle-mutation lanes address these risks independently. Fixed pull-request
seeds provide a replayable baseline; scheduled campaigns vary the seed and
retain full requests, edit provenance, worker identities, and mismatches. A
passing finite campaign is evidence for its recorded inputs and resource bounds,
not a mathematical proof of grammar completeness or asymptotic performance.

== Snapshot extraction audit

The parsing inventory includes ordinary and named files, exact header and
statement goals, every nonempty REPL input, and each Roc file embedded in docs
or dev-object snapshots. This exercises syntax only: it does not execute REPL
sessions, extract documentation, or run code-generation backends.

The pinned snapshot runner's `src/snapshot_tool/main.zig` is the extraction
authority. Its goal mapping is at line 1008, multi-file extraction at line 3639,
REPL input classification at line 4275, and literal `»` splitting plus ASCII
trimming at line 4974. REPL input dispatch uses the `repl` worker mode; the
importer never guesses whether text is a declaration using token heuristics.
Each extracted input retains its original snapshot path and Git blob, byte
range within that blob, exact extracted-byte checksum, and final parser-input
checksum. `source_escapes=true` records the runner's explicit carriage-return
transformation. The original compiler snapshot output is not used as an
acceptance oracle.

Regression tests retain complete immutable upstream blobs for REPL,
dev-object, and docs extraction, check their Git object identities, and verify
all byte slices and hashes. In particular, documentation comments beginning
with `##` inside a Roc fence remain source text. Unknown modes, malformed
fences and empty inventories fail explicitly rather than becoming passing
skips. The only excluded inventory item is the snapshot directory README.
