[#markup-facts]
= Query markup facts for a consumer
:idprefix: _
:idseparator: _

Use `MarkupFacts` when compiling a parsed tree into another representation or
choosing how to bind an attribute value. The facts share the parser's vocabulary
and preserve the element namespace and the attribute's expanded identity.
Consumers do not need a second table of element, ARIA or handler names.

`is_known_element` tests the built-in HTML, SVG and MathML vocabulary.
`is_custom_element_name` tests current HTML custom-element names; it does not
infer a namespace. Unknown names can still be constructed with `DomName`, and
parser extension options remain available independently of these predicates.

`element_names(namespace)` supplies the canonical local spellings for that
namespace's built-in authoring vocabulary. `aria_attribute_names` supplies known
unnamespaced ARIA spellings, including retained deprecated names. Both lists
are unique and sorted by ASCII spelling. SVG case is preserved, so a consumer
can suggest `linearGradient` without maintaining a second spelling table:

[source,roc]
----
include::examples/markup-vocabulary.roc[tag=names]
----

An absent or unknown namespace has an empty element list. Custom and extension
names are not finite candidate sets. These lists describe the current supported
vocabulary, rather than every name that DOM constructors or browser recovery
can retain. Enumeration and membership use the same parser-owned vocabulary.

== Attribute values

`is_boolean_attribute(element, attribute)` identifies HTML presence/absence
booleans on their relevant elements. It does not turn SVG or MathML `true`/`false`
values, or ARIA states, into HTML booleans. Namespaced attributes are distinct
from unnamespaced attributes with the same local spelling.

`enumerated_values` returns known single-value keywords, including shared ARIA
states for HTML, SVG and MathML. For example, `hidden` has empty, `hidden` and
`until-found` keywords; it is not a presence/absence boolean. `NotEnumerated`
means no keyword fact is provided: numbers, token lists and unknown metadata
also return it. The result does not model browser missing-value or invalid-value
defaults. Preserve the original value rather than lowercasing it indiscriminately.

`attribute_grammar` exposes the grammar used by the current parser checks.
Consumer metadata can be more detailed than those checks: an attribute whose
parser grammar is a generic language can still have boolean or enumerated facts.
The coverage manifest describes the parser's validation boundaries.

== HTML text and void behavior

`is_void_element` uses the HTML namespace and local name. An SVG element named
`br` is not an HTML void element. `text_behavior(element, scripting)` preserves
`Data`, `Rcdata`, `RawText`, `ScriptData` and `Plaintext`; it does not collapse
script and plaintext into a generic raw-text mode. HTML `noscript` uses
`RawText` when scripting is enabled and `Data` otherwise. Foreign content uses
`Data`, and XML source keeps its separate grammar.

=== Initial newlines when emitting HTML

`drops_initial_newline(element)` identifies HTML `pre`, `listing` and `textarea`.
After their emitted HTML start tag, the parser can consume one immediately
following LF character token. This describes HTML parsing, independently of
whether an authoring vocabulary accepts a historical name. XML parsing and
ordinary DOM text mutation do not have this rule. Merely choosing a `textarea`
fragment context does not process a start tag or activate the rule.

For a serializer producing several bindings, `initial_newline(element)` seeds
`Pending` or `Preserve`. Pass actual emitted token events through
`initial_newline_step`; it returns the next state, adjusted token and `skipped`
flag. An empty text binding emits no token, so it retains `Pending`. A comment
consumes the pending position, so the next text's LF is retained. Nonempty text
also consumes it, removing at most one initial LF.

The events contain decoded text after HTML input newline preprocessing and
character-reference decoding. A numeric reference to CR is still CR; literal
source CR/CRLF has already become LF. In RCDATA, serialized comment spelling is
text beginning with `<`, rather than a comment token, and that character consumes
the pending position. Escaping and the element's text behavior remain separate
serializer responsibilities. These facts do not suppress syntax diagnostics;
choose recovery independently, as described in
xref:exact-structure.adoc#exact-structure[the recovery and authored-structure controls].

== A consumer policy for handler attributes

`is_event_handler(element, attribute)` checks the element namespace and the
attribute namespace/local name. It recognizes MathML `onclick` even inside an
SVG metadata extension subtree, and SVG `oninput`. An attribute named `online`
is not a handler. A namespaced attribute with local `onclick`, or an
unnamespaced attribute with local `e:onclick`, is also distinct from the
unnamespaced handler.

The https://html.spec.whatwg.org/multipage/webappapis.html#event-handlers-on-elements-document-objects-and-window-objects[HTML event-handler rules],
https://svgwg.org/svg2-draft/types.html#InterfaceSVGElement[SVG interfaces] and
https://w3c.github.io/mathml-core/#dom-and-javascript[MathML interfaces] define
the namespace boundaries.
