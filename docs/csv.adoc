[#csv]
= Read CSV data
:idprefix: _
:idseparator: _

This chapter shows how to turn comma-separated text into Roc values: as
records chosen by the type you ask for, as tuples when the file has no
header, as raw fields, and with hand-built record parsers when a column needs
custom handling. It also shows how to tell the user which row was wrong. It
is for Roc programmers who have added `parser` to their app's dependencies.

Every example on this page comes from
link:{src}/docs/examples/csv-guide.roc[`docs/examples/csv-guide.roc`], which
CI runs, and imports `parser.CSV`, `parser.Parser` and `parser.Utf8`.

`MissingRequiredField(name)` is not declared by `CSV.parse`: the compiler adds
it to the error type of any decoder whose record has required fields, so
include it in your annotation. Columns that no field names are ignored, and
when two columns share a name the last one wins.

A cell decodes according to its field's type:

[cols="1,3",options="header"]
|===
|Type |Accepted cell text

|`Str`
|Any text, kept exactly, including leading and trailing spaces.

|`Bool`
|`true` or `false` in any letter case.

|`U8` … `U128`, `I8` … `I128`
|ASCII digits with an optional leading `+` (or `-` for signed types) that fit
in the type. Spaces, `_` and `0x` prefixes are rejected.

|`Dec`
|An optional sign, digits and an optional fraction: `1.50`, `-2`, `.5`.

|`F32`, `F64`
|An optional sign, then `inf`, `infinity` or `nan` in any letter case, or a
decimal number with an optional fraction and exponent: `12`, `1.5`, `.5`,
`5.`, `1e-3`, `2.5E+10`. Values too large become infinity and values too small
become zero.

|Tags without payloads
|The tag name, such as `Active`.
|===

These match Rust's `from_str` for each number type. A field that is a
record, a tuple or a tag with a payload fails with an `InvalidCsv` error
when it is decoded; a field that is a list or a dictionary is a compile-time
error, because a CSV cell cannot hold one.

=== Optional columns, empty cells and header spelling

A field of type `Try(a, [Missing])` is `Err(Missing)` when the file has no
such column. A field of type `Try(a, [Null])` is `Err(Null)` when its cell is
empty. `CSV.parse_normalized` matches header names after trimming spaces,
lowercasing ASCII letters and turning runs of spaces, `-` and `_` into one

=== Row width and blank lines

Blank lines are skipped. Every other row must have exactly as many fields as
the header: a shorter row and a longer row are both an `InvalidCsv` error
naming the row, so that a misplaced comma cannot shift values into the wrong
columns. A header with no data rows, and empty input, decode to an empty list.

== Hand-built record parsers

When a column needs custom handling, such as a list stored in one cell,
describe one row with `CSV.record`, giving it a function that takes one
argument per column, then add one `.keep(CSV.field(...))` per column in
order. A field parser is any `Parser(Utf8.Bytes, a, problem)`; `CSV.string`,
`CSV.u64` and `CSV.f64` read cells with the rules above:

[#csv-streaming]
== Read and write large files

Pass `CSV.decoder(limits)` to `Streaming.read_iter(chunks, decoder)` for an
`Iter(List(U8))`, or to `Streaming.read_stream(chunks, decoder)` for an effectful
`Stream(Try(List(U8), source_error))`. Readers yield `Value(record)`, recoverable
`Rejected(error)` events when configured, and `Finished(report)` after complete
validation. Consume through `Finished`; stopping early validates only a prefix.
Source failures remain distinct from CSV failures.

Chunks may end inside UTF-8 characters, quoted multiline fields, doubled quotes,
or CRLF. Empty chunks do not end the document. For manual backpressure call
`decoder.step(bytes, More | Final)` and retain the returned state.

`CSV.positional_decoder(parser, limits)` applies a custom record parser.
`CSV.typed_decoder(header_mode, limits)` infers the row type; header modes are
`Exact`, `Normalized`, or `Absent`. Headers are retained once; completed rows
leave the decoder. Default limits are 16 MiB per field, 64 MiB per unfinished
record, and 65,536 fields. Set `CSV.ReaderProps` for larger individual records.

Configure recovery with `decoder.with_errors({ error_policy: ReportInvalidRecords })`.
The default `Streaming.ReadProps` stops on the first error. `SkipInvalidRecords`
counts and skips a row that fails typed decoding; `ReportInvalidRecords` also
emits its `Rejected` diagnostic. Both allow at most `max_errors` rejected
records (1,000 by default). The next rejection is terminal and retains its
triggering diagnostic. Malformed CSV syntax and resource limits are terminal
in every mode because their record boundaries cannot safely be guessed.

`Streaming.collect` fails on a rejection, skipped records, or a missing
completion event. Use `Streaming.collect_report` to explicitly collect the
values, reported diagnostics, and completion counts. Collecting retains all
output; ordinary iteration or folding keeps parser memory bounded by the
current chunk, unfinished record, header, and consumer-retained values.

`Streaming.write_iter(records, CSV.encoder(options))` and its `write_stream`
counterpart validate each complete record before emitting its bytes.
Set output bounds with `CSV.encoder(options).with_chunk_bytes(bytes)`; the
default is 64 KiB and zero is rejected.
`CSV.WriteProps` defaults to necessary quoting and CRLF. Set `quoting: Always`
or `line_ending: Lf`/`Cr` for another output dialect. A record must contain at
least one field; a lone empty field is quoted so it survives a round trip.

The complete https://github.com/lukewilliamboswell/roc-parser/blob/main/examples/csv-streaming.roc[streaming example]
connects basic-cli's file or stdin chunks to CSV parsing and a bounded file
writer. It never reads the entire document at once:

[source,bash]
----
roc examples/csv-streaming.roc normalized.csv input.csv
----

The whole-document raw scanner remains optimized for complete buffers and is
compared against the incremental scanner by fuzzing arbitrary bytes and chunk
boundaries. Typed complete-document and streaming APIs report syntax and
decoding failures in the order their records are encountered.

== Report which row failed

Native CSV failures return `InvalidCsv(error)`. Custom positional parser failures
return `InvalidRow(error)`, preserving their own typed problem under `ParserFailure`.
The `CSV.Error` record says where the problem is:

[cols="1,3",options="header"]
|===
|Field |Meaning

|`record`, `field`
|The one-based record and field numbers. Records count every record of the
input, including the header row and blank lines.

|`line`, `column`
|The one-based line and byte column where the field (or, when the field
does not exist, the record) starts. They are `0` from `CSV.decode`, which
does not see the text.

|`problem`
|A descriptive tagged failure with structured limits, expected scalar type,
widths or offending source bytes. Native cell payloads retain at most 40 bytes.
Match tags to classify errors; render them at the application boundary.
|===

== Which CSV files are accepted

The dialect is RFC 4180 with the relaxations that Python's `csv` module (in
strict mode) and Rust's `csv` crate also accept:

* Fields are separated by `,`. Records end with CRLF, LF or a lone CR, and the
  line break after the last record is optional.
* An unquoted field is any run of bytes other than `,`, CR and LF. A `"`
  inside an unquoted field is an ordinary character.
* A field that starts with `"` is quoted. It may contain `,`, CR and LF, and
  `""` stands for one `"`. The closing quote must be followed by `,`, a line
  break or the end of input; an unterminated quoted field is an error.
* Spaces and tabs are kept as part of the field.
* Empty input has no records. A blank line in the middle of the input is a
  record with one empty field.
* Rows may have different numbers of fields (the typed decoders then check
  the width).

== Limitations

* The separator is always `,`. Tab- or semicolon-separated files are not
  supported.
* A UTF-8 byte order mark is not removed; it becomes part of the first field.
* Whole-document convenience functions retain the input and collected output.
  Use the incremental APIs for files that approach the application memory limit.

For every function and type in the module, see the
link:{api}CSV[CSV API reference].

[#csv-performance]
== Performance

Whole-document raw scanning uses SIMD delimiter searches and can share field
slices with the input. Incremental scanning owns unfinished records so completed
records do not pin old source chunks. Typed decoding adds each conversion's
cost, and whole-document collection retains the resulting values.

Run `scripts/bench.py --formats csv` for separate collection and string-record
consumption comparisons. `bench/roc/csv-file-stream.roc` reads a real file or
stdin without preloading it and reports record count, content checksum, first-item
latency and elapsed time including reads. Use that driver for source-retention
measurements; parse-only benchmarks intentionally keep their input in memory.
See <<benchmarks>> and <<performance>> for build modes, receipts and comparison
requirements.

The conformance review uses the shared <<correctness-oracle-cache,correctness oracle cache>>.
