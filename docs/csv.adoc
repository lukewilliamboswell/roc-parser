[#csv]
= Read CSV data

This chapter shows how to turn comma-separated text into Roc values: first
as plain lists of strings, then as typed records, and how to tell the user
which row was wrong when decoding fails. It is for Roc programmers who have
added `parser` to their app's dependencies. You do not need to know the
combinator library; the CSV module wraps the parts you need.

Every example on this page comes from
link:{src}/docs/examples/csv-guide.roc[`docs/examples/csv-guide.roc`], which
CI runs, and imports `parser.CSV` and `parser.Parser`.

The first row is returned as data. CSV has no reliable way to say that a row

files have one.

`CSV.parse_str_to_csv` also parses text into a `CSV` value, but that type is
opaque: you can only pass it on to `CSV.parse_csv` with a record parser. Use a
record parser such as `all_fields` above when you want the raw strings.

A record parser must use every field in the row. A row with more fields than
`.keep` calls fails, and so does a row with fewer.

The built-in field parsers accept these forms:

[cols="1,3"]
|===
|Parser |Accepted field text

|`CSV.string`
|Any valid UTF-8, kept exactly, including leading and trailing spaces.

|`CSV.u64`
|ASCII digits with an optional leading `+`, and a value that fits in a `U64`.
Spaces, `_`, `-` and `0x` prefixes are rejected.

|`CSV.f64`
|An optional sign, then `inf`, `infinity` or `nan` in any letter case, or a
decimal number with an optional fraction and exponent: `12`, `1.5`, `.5`,
`5.`, `1e-3`, `2.5E+10`. Values too large become infinity and values too small
become zero. Spaces, `_` and hexadecimal forms are rejected.
|===

These match Rust's `u64::from_str` and `f64::from_str`. For any other column
type, map a string field yourself; for example
`CSV.string.map(|s| Str.split_on(s, ";"))` reads a list stored in one field.

== Report which row failed

`CSV.parse_str` stops at the first problem and returns one of three errors:

[cols="1,3"]
|===
|Error |Meaning

|`SyntaxError(rest)`
|The text is not valid CSV. `rest` is the input from the record that could
not be read, for example an unterminated quoted field.

|`ParsingFailure(message)`
|A field did not match its parser, or a row ran out of fields. The message
names the field and ends with the one-based record number and the record's
fields.

|`ParsingIncomplete(fields)`
|The record parser finished but the row still had `fields` left over.
|===

== Which CSV files are accepted

The dialect is RFC 4180 with the relaxations that Python's `csv` module (in
strict mode) and Rust's `csv` crate also accept:

* Fields are separated by `,`. Records end with CRLF, LF or a lone CR, and the
  line break after the last record is optional.
* An unquoted field is any run of bytes other than `,`, CR and LF. A `"`
  inside an unquoted field is an ordinary character.
* A field that starts with `"` is quoted. It may contain `,`, CR and LF, and
  `""` stands for one `"`. The closing quote must be followed by `,`, a line
  break or the end of input; an unterminated quoted field is a `SyntaxError`.
* Spaces and tabs are kept as part of the field.
* Empty input has no records. A blank line in the middle of the input is a
  record with one empty field.
* Rows may have different numbers of fields.

== Limitations

* The separator is always `,`. Tab- or semicolon-separated files are not
  supported.
* A UTF-8 byte order mark is not removed; it becomes part of the first field.
* Headers are not interpreted, so columns are matched by position, not name.
* The whole input is parsed before decoding starts, so very large files are
  held in memory.

For every function and type in the module, see the
link:{api}CSV[CSV API reference].

[#csv-performance]
== Performance

Reading every field as a string runs at about 150 MB/s on an Apple M2, from
a 1.6 KB export to a 1 MiB file: as fast as Rust's `csv` crate, 2.5 times
slower than Go's `encoding/csv` and twice as fast as Python's C `csv` module.
The parser is a byte scanner and stays linear on very wide rows and long runs
of escaped quotes. Decoding typed columns with `CSV.u64`, `CSV.f64` and
friends adds the cost of each conversion. The whole file and every field are
held in memory: about 13 MiB of peak memory for a 1 MiB file. See
<<performance>> for the method and caveats.
