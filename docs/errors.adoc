[#errors]
= Report parse errors
:idprefix: _
:idseparator: _

Parser failures carry descriptive tags and structured payloads. Match the tags
when deciding what to do; render text when displaying a failure. Locations,
configured limits, expected types and offending source values remain available
without extracting them from a diagnostic string.

The examples below come from
{src}/docs/examples/errors-report.roc[errors-report.roc]. Their complete output is
checked against
{src}/docs/examples/errors-report.expected[errors-report.expected].

== Shared diagnostic metadata

A diagnostic is `Parser.Diagnostic(problem)`, a transparent nominal record with
`problem`, `location` and `path`. The problem remains a descriptive tag union
owned by the format. Source strings carry names, keys or authored values;
callers never need to match prose to distinguish failures.

[cols="1,3",options="header"]
|===
|Location |Meaning
|`Text({ offset, line, column })` |Original byte offset and one-based physical line and byte column
|`ByteOffset(offset)` |Original byte offset when text coordinates are not retained
|`LineColumn({ line, column })` |Known text coordinates without an original byte offset
|`InputOffset(index)` |Element index in the generic parser's input, which may not be bytes
|`Unavailable(reason)` |`NotRetained`, `GeneratedValue` or `NotApplicable`; no fabricated zero position
|===

The logical `path` is independent of the physical location. Its segments are
`Record(number)`, `Field(number)`, `Index(index)`, `Key(key)` and `Source(name)`.
Record and field numbers are one-based; indexes are zero-based. A decoded value
can therefore retain a key or field identity even when source bytes are gone.

[cols="1,2",options="header"]
|===
|Operation |Failure
|Format `parse_str`, `parse_bytes` and `validate` constructors
|A native tag such as `InvalidYaml(error)`, `InvalidXml(error)`, `InvalidNamespace(error)`, `InvalidJsonValue(error)`, `InvalidCsv(error)` or `InvalidHttp(error)`
|`parser.parse`, `parser.run`, `parser.parse_str`, `parser.run_str`
|`ParseError(diagnostic)` with the grammar's problem union plus generic runner failures
|CSV positional row parser
|Its generic runner preserves `InvalidCsv(error)` or `InvalidRow(error)` inside `diagnostic.problem`
|`value.encode(props)`
|A typed format error describing why a programmatically constructed value cannot be written
|`Markdown.parse_str`
|None: every input is a Markdown document
|===

Resource failures retain `max` and `observed`. `Exact(count)` is a complete
count; `AtLeast(count)` records the first proven violation without scanning the
remaining input. Offending scalar values use owned bounded excerpts containing
at most forty bytes and the original `total_bytes`; keeping a failure does not
retain the complete input buffer. Complete identifiers remain available when
identity is needed.

Quotation hooks render typed failures into `BadQuotedBytes(Str)` because
compiler diagnostics require text. Runtime validation retains native tags.
Failure unions compose with `?`, including application and I/O errors.
`InvalidJsonValue` remains distinct from builtin `Json`'s `InvalidJson`.

records. Physical coordinates identify the failed field. Custom field parsers

`ParserFailure`; the row adapter adds the record context.

that parser.

[#_your_own_parsers_say_where_and_what]
== Streaming and custom parsers

Chunk readers forward native format failures directly. `SourceErr(cause)`
preserves an I/O failure unchanged; it never finalizes truncated input as EOF.
A safely framed invalid record can produce `Rejected(nativeError)` when recovery
is configured. Resource limits, broken framing and invalid encoding remain
terminal. Adapter failures are structured `DecoderProtocol` or
`RecoveryLimitExceeded` diagnostics. See <<streaming>>.

Define domain failures with payloads, such as `InvalidTime({ hour, minute })`.
A custom primitive returns
`Err(ParseError(Parser.Diagnostic.{ problem, location: InputOffset(offset), path: [] }))`.
Alternatively validate a parsed value with `.map(...).flatten()`.
The runner preserves the furthest failure and explicit logical context;
`parse_str` and `run_str` turn inferred byte indexes into original text positions.

When combining a native format parser with another grammar, use
`.map_problem(|problem| JsonProblem(problem))` to give its problems a domain tag.
This changes problem identity while preserving diagnostic locations and paths.
Primitive factories such as `Parser.Utf8.digits({})` and `CSV.string({})` infer
the surrounding extensible problem type.
