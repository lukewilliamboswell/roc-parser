[#errors]
= Report parse errors
:idprefix: _
:idseparator: _

Parser failures carry descriptive tags and structured payloads. Match the tags
when deciding what to do; render text when displaying a failure. Locations,
configured limits, expected types and offending source values remain available
without extracting them from a diagnostic string.

The examples below come from
{src}/docs/examples/errors-report.roc[errors-report.roc]. Their complete output is
checked against
{src}/docs/examples/errors-report.expected[errors-report.expected].

== Summary

[cols="1,2,2",options="header"]
|===
|Function |Failure |Location and details

|`QIF.parse_str`, `OFX.parse_str`
|`InvalidQif(error)`, `InvalidOfx(error)`
|Original byte `offset`, one-based `line` and byte `column`, and a typed `problem`.

|`Yaml.parse_str`, `Yaml.decode`, `Xml.parse_str`, `XmlNs.parse_str`, `JsonValue.parse_str`
|`InvalidYaml(error)`, `InvalidXml(error)`, `InvalidNamespace(error)`, `InvalidJsonValue(error)`
|One-based `line` and byte `column`, and a typed `problem` describing syntax,
limits or selected validation checks.

|`CSV.parse`, `CSV.parse_records`
|`InvalidCsv(error)`
|One-based `record`, `field`, `line` and byte `column`, and a typed `problem`.

|`CSV.parse_with`, `CSV.decode`
|`InvalidCsv(error)` or `InvalidRow(error)`
|CSV syntax failures remain native errors. `InvalidRow` preserves a custom
parser's problem under `ParserFailure`, with the row and field location.
Coordinates unavailable to `CSV.decode` are zero.

|`CSV.parse`, `Yaml.decode`
|`MissingRequiredField(name)`
|A required record field had no column or mapping key. `name` is source context.

|`HTTP.parse_request`, `HTTP.parse_response`, `HTTP.parse_requests`
|`InvalidHttp({ offset, problem })`
|Byte offset and a typed HTTP syntax, framing or semantic problem.

|`JsonValue.to_str`, `JsonValue.to_str_with`
|`InvalidNumber(text)`, `DuplicateKey(key)`, `TooDeep`
|Why a value constructed in code cannot be written as JSON.

|`Markdown.parse_str`
|None
|Every input is a Markdown document.

|`Utf8.parse_str`, `Parser.parse`
|`ParseError({ offset, problem })`
|The furthest failure, including a custom parser's own tags. Leftover input
produces `UnexpectedInput` unless a more precise failure reached that position.
|===

Format problems belong to their module's `Problem` union. A `Str` payload holds
source data or application context, such as a field name or invalid number;
it does not identify the failure. Quotation conversions render these problems
into `BadQuotedBytes(Str)` because compiler diagnostics require text.

Outer failure unions compose with `?`, including functions that also return I/O
errors. `JsonValue` uses `InvalidJsonValue`, so it can coexist with builtin
`Json`'s `InvalidJson` without a tag collision (see <<json-builtin>>).

== CSV: report the record and field

Record and field numbers count every input record, including headers and blank
lines. Physical positions identify the start of a failed field. A custom field
parser's byte offset is retained inside `FieldProblem`; the outer offset is its
column within the record.

that parser.

[#_your_own_parsers_say_where_and_what]
== Streaming and custom parsers

All chunk readers use the same failure contract. `SourceErr` preserves an I/O
failure; `ParseErr` carries a terminal format failure. A safely framed rejected
record can produce `Rejected(problem)` when recovery is configured. Resource
limits, broken framing and invalid encoding remain terminal. See <<streaming>>
for error policies and completion validation.

Define domain failures as tags with payloads, such as
`InvalidTime({ hour, minute })`. Return them from a custom parser or validate a
parsed value with `.map(...).flatten()`. `Parser(input, value, problem)` preserves
the problem type through combinators and runners, together with the furthest
byte offset. Convert that offset to an application location with
`Literal.position(source, offset)` when the input is UTF-8 text.

When embedding a native format parser in another grammar, give its failures a
domain tag with `.map_problem(|problem| JsonProblem(problem))`. The mapper
preserves byte offsets and furthest failures while allowing the surrounding
grammar to use its own problem tags. Primitive factories such as
`Utf8.digits({})` and `CSV.string({})` infer the shared extensible problem type.
