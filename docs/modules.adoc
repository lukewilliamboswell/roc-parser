[#modules]
= Modules

This chapter is a map of the package for readers who know some Roc and want
to find the right module and entry point for an input format. It says what each
module is for, which types and functions you start from, and how the modules
fit together. The {api}[API reference] has the full signature and
documentation of every type and function, generated from the source.

== The modules at a glance

The package exposes seven modules. Two are general-purpose building blocks; the
other five are ready-made parsers for one format each.

[cols="1,3,3",options="header"]
|===
|Module |Use it to |Start from

|{api}Parser/[`Parser`]
|Combine small parsers into larger ones, for any input type
|`Parser.const`, `keep`, `skip`, `map`, `one_of`, `many`, `sep_by`

|{api}Utf8/[`Utf8`]
|Parse text: match bytes, strings and digits, and run a parser on a `Str`
|`Utf8.parse_str`, `string`, `codeunit`, `digits`

|{api}CSV/[`CSV`]
|Read comma-separated values, raw or decoded into your own record type
|`CSV.parse_str`, `CSV.record`, `CSV.field`, `CSV.parse_str_to_csv`

|{api}HTTP/[`HTTP`]
|Read one HTTP/1.1 request or response message, including its body
|`HTTP.request`, `HTTP.response`

|{api}Markdown/[`Markdown`]
|Turn CommonMark and GitHub Flavored Markdown into a syntax tree
|`Markdown.all`, `Markdown.inlines`

|{api}Xml/[`Xml`]
|Check that an XML document is well-formed and read it as a tree
|`Xml.parse_str`, `Xml.xml_parser`

|{api}Yaml/[`Yaml`]
|Read a YAML configuration file or Markdown frontmatter
|`Yaml.parse_str`
|===

== How the modules fit together

A `Parser(input, a)` is a value that describes how to read an `a` from the
start of an `input`. Running it returns the value and the input it did not
consume, or a `ParseError` with a message and an offset. `Parser` provides the combinators that
build parsers from parsers; `Utf8` provides the parsers that read text, with
`Utf8.Bytes` (a `List(U8)`) as the input type.

The format modules use these in two ways:

* `CSV`, `HTTP` and `Markdown` expose parsers (`Parser(Utf8.Bytes, ...)` or,
  for CSV records, `Parser(CSV.CSVRecord, ...)`). Run them with
  `Utf8.parse_str`, or embed them in a larger parser.
* `Xml` and `Yaml` expose a `parse_str` function that takes a whole document
  and returns either the value or an error record with a one-based line and
  column. `Xml.xml_parser` is also available as a parser for embedding.

== Parser

`Parser` is the combinator library. Use it when you are writing a parser for a
format this package does not cover, or extending one of the format parsers.

* `Parser(input, a)` is the opaque parser type, and `ParseResult(input, a)` is
  what one step of parsing returns.
* Build values with `const` and feed it parsed arguments with `keep`; read and
  discard syntax with `skip`.
* Choose between alternatives with `alt` and `one_of`. Each alternative starts
  from the same input, so a failed alternative never consumes anything.
* Repeat with `many`, `one_or_more`, `sep_by` and `sep_by1`. Repetition stops
  when an element fails or consumes nothing.
* Convert results with `map`, `map2`, `map3`, `apply` and `flatten`.
* Run a parser with `parse` (whole input) or `parse_partial` (leaving the
  rest). For text, prefer the `Utf8` functions below.
* `build_primitive_parser` turns your own function into a parser when no
  combinator fits; `lazy` defers building a parser for recursive grammars.

== Utf8

`Utf8` holds the text parsers and the functions that run a parser on text.

* `Utf8.parse_str` runs a parser on a whole `Str` and reports leftover text
  as a `ParseError`. `parse_str_partial`, `parse_bytes` and
  `parse_bytes_partial` cover partial input and byte input.
* `codeunit`, `codeunit_satisfies`, `any_codeunit`, `utf8` and `string` match
  bytes and literal text. `digit` and `digits` read unsigned decimal numbers.
* `any_thing` and `any_string` consume the rest of the input.
* `one_of` is the text version of `Parser.one_of`.

The parsers work on bytes, not characters: `codeunit('é')` is not possible,
because `é` is two bytes in UTF-8. Use `string("é")` instead.

== CSV

`CSV` reads RFC 4180 comma-separated values; the module documentation lists the
exact dialect.

* `CSV.parse_str` parses the text and decodes every record with a record
  parser you build from `CSV.record` and `CSV.field`. Field parsers `CSV.string`,
  `CSV.u64` and `CSV.f64` are provided, and any `Parser(Utf8.Bytes, a)` works.
* `CSV.parse_str_to_csv` returns the raw records as `List(List(Utf8.Bytes))`
  when rows differ in shape or you want to inspect them first; decode them
  later with `CSV.parse_csv`.

Every row is data: a heading row is not treated specially, so skip or decode
it yourself.

== HTTP

`HTTP` reads one HTTP/1.1 (or HTTP/1.0) message: start line, header fields and
body.

* `HTTP.request` and `HTTP.response` are parsers. With `Utf8.parse_str` they
  reject trailing data; with `Utf8.parse_bytes_partial` they return the bytes
  of the next pipelined message.
* `Request` and `Response` are records; `Header`, `Method` and `HttpVersion`
  describe their fields.

The parser decodes chunked bodies and rejects any message whose length is
ambiguous, which is what protects a proxy from request smuggling. It does not
open connections, send messages, or know which request a response answers; see
<<conformance,Conformance>> for what that means for HEAD and CONNECT.

== Markdown

`Markdown` turns CommonMark 0.31.2 text, with the GitHub Flavored Markdown
tables, task lists, strikethrough and extended autolinks, into a tree of
`Markdown` blocks and `Markdown.Inline` nodes.

* `Markdown.all` parses a whole document into `List(Markdown)`. Markdown has
  no syntax errors, so it accepts every input.
* `Markdown.inlines` parses inline content only, such as a single line of
  text.
* A leading block between `---` lines becomes a `Frontmatter` node that you can
  pass to `Yaml.parse_str`.
* `to_debug_str` and `inline_to_debug_str` print a tree for tests and
  debugging.

The module does not render HTML; walk the tree to produce your own output.

== Xml

`Xml` checks XML 1.0 well-formedness and returns the document as a tree of
`Xml.Node` values (`Element` and `Text`).

* `Xml.parse_str` returns an `Xml` record with the optional declaration and
  the root element, or an `XmlError` with line, column and message.
* `Xml.xml_parser` is the same parser for use inside a larger parser.

Documents with a `<!DOCTYPE>` declaration are rejected, namespaces are not
interpreted, and comments and processing instructions are checked and then
dropped.

== Yaml

`Yaml` reads a practical subset of YAML 1.2 aimed at configuration files and
Markdown frontmatter.

* `Yaml.parse_str` returns a `Yaml` value (`Null`, `Bool`, `Int`, `Float`,
  `String`, `Sequence` or `Mapping`) or a `YamlError` with line, column and
  message.
* `Yaml.to_inspect` prints a value for tests and debugging.

Anchors, aliases, tags, directives, complex keys, multi-line flow collections,
multi-line plain or quoted scalars and multi-document streams are rejected
rather than misread. Nesting is limited to 100 levels.

== Choosing between modules

[cols="2,3",options="header"]
|===
|If your input is |Use
|A small text format of your own, such as a command or a log line |`Parser` with `Utf8`
|A spreadsheet export or other comma-separated data |`CSV`
|Raw bytes of an HTTP/1.1 message from a socket or a capture |`HTTP`
|Documentation, notes or a README |`Markdown`
|A configuration file, or the frontmatter of a Markdown file |`Yaml`
|An XML document without a document type declaration, such as SVG or a feed |`Xml`
|JSON, TOML, or YAML that uses anchors or several documents |Another package: these modules do not support them
|===

<<conformance,Conformance>> lists, for each format, the specification it
follows, how that is checked, and the known gaps.
