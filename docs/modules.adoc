== The modules at a glance

The package exposes fifteen roots. Shared parser primitives and quotation
helpers live under `Parser`; format-specific constructors live with their values.

[cols="1,3,3",options="header"]
|===
|Module |Use it to |Start from
|`AsciiDoc` |Parse and preprocess AsciiDoc |`AsciiDoc.parse_str(source, {})`
|`CSV` |Read raw fields or decode records |`CSV.parse_str(source, {})`, `CSV.decode_str(source, {})`
|`HTTP` |Read request and response messages |`HTTP.Request.parse_bytes(bytes, {})`, `HTTP.Response.parser({})`
|`Html` |Check HTML documents, fragments and templates |`Html.parse_str`, `Html.parse_fragment`, `Html.RepairContext`
|`JsonValue` |Read lossless JSON trees and record streams |`JsonValue.parse_str`, `JsonValue.record_decoder`, `value.encode({})`
|`Markdown` |Parse CommonMark and GFM |`Markdown.parse_str(source, {})`
|`Markup` |Use shared names, source trees, contexts and templates |`Markup.Name`, `Markup.Context`, `Markup.Template.Plan`
|`MathML` |Check MathML documents and fragments |`MathML.parse_str`, `MathML.parse_fragment`
|`OFX` |Read and write financial statements |`OFX.parse_str`, `OFX.decoder`, `OFX.encoder`
|`Parser` |Build parsers and shared streaming descriptors |`Parser.const`, `Parser.Utf8`, `Parser.Quotation`
|`QIF` |Read and write Quicken records |`QIF.parse_str`, `QIF.decoder`, `QIF.encoder`
|`RocSyntax` |Retain Roc tokens, trees and diagnostics |`RocSyntax.parse_str`, `RocSyntax.parse_bytes`
|`Svg` |Check SVG markup and path data |`Svg.parse_str`, `Svg.Path.parse_str`
|`Xml` |Read raw or namespace-resolved XML |`Xml.parse_str`, `Xml.Namespaced.parse_str`, `Xml.reader`
|`Yaml` |Read YAML trees or decode configuration records |`Yaml.parse_str`, `Yaml.decode_str`
|===

== How the modules fit together

Constructors take a source and a defaulted props record, such as
`Xml.parse_str(source, {})`. Configure that same operation through its props;
there is no separate `parse_with` variant. A parser constructor such as
`Xml.parser({})` returns a reusable value: `parser.parse_str(source)` consumes
all input, while `parser.run_str(source)` returns `{ value, rest }`.

Failures carry `Parser.Diagnostic(problem)`: `{ problem, location, path }`.
Native formats wrap this in their own failure tag, such as `InvalidXml`.
Generic parser runners use `ParseError`. See <<errors>> for locations, logical
paths, bounded source excerpts and rendering.

Streaming uses the same receiver methods for every format. Construct a decoder,
then call `decoder.read_iter(chunks)`, `decoder.read_stream(source)` or
`decoder.collect(chunks)`. Configure recovery in the constructor's `errors`
props. Encoders provide `write_iter` and `write_stream`; see <<streaming>>.

Checked quotations use `from_quote`. Runtime `validate` returns native typed
failures; `Parser.Quotation.require` asserts a checked constant, and quotation
hooks render compiler text at that boundary. See <<compile-time-parsing>>.

== Parser

`Parser(input, value, problem)` describes a computation over input. Compose it
with receiver operations such as `keep`, `skip`, `map`, `many` and `sep_by`.
`Parser.one_of` chooses alternatives, and `Parser.custom` adapts a primitive
with a structured diagnostic. See <<combinator-primer>> and <<combinators>>.

[#_utf8]
== Parser.Utf8

`Parser.Utf8` owns byte, string and digit primitives. `Parser.Utf8.Bytes` is
`List(U8)`. Text runners are methods of the parser value, so a parser built
from these primitives uses `parser.parse_str(source)` or `parser.run_str(source)`.

== CSV

`CSV.parse_str(source, {})` returns a nominal document with raw `.records`.
`CSV.decode_str(source, {})` infers a record type from use. For positional
conversion, build a `CSV.record` parser with `CSV.field` and pass it to
`CSV.rows_parser({ row })`. Its generic runner returns `ParseError`, preserving
`InvalidCsv` or `InvalidRow` inside the problem union. See <<csv>>.

== HTTP

`HTTP.Request` and `HTTP.Response` own complete `parse_bytes` constructors and
prefix `parser` constructors. A parsed message offers `message.header(name)`.
Their decoders emit message heads, body fragments, trailers and boundaries;
response decoding also takes request methods. The parser operates on bytes and
performs no network I/O. See <<http>>.

== JsonValue

`JsonValue.parse_str(source, props)` reads a tree while preserving member order
and number spelling. Props select explicit relaxations and resource bounds.
Use receiver methods such as `get`, `at`, `get_path` and `as_i64` to inspect a
value. `value.encode(props)` returns validated UTF-8 bytes; `JsonValue.record_decoder`
and `JsonValue.record_encoder` provide record streams. See <<json>>.

== Markdown

`Markdown.parse_str(source, {})` returns blocks directly: every input is valid
Markdown. `Markdown.parse_inlines` reads inline content. Tree values retain
links and raw HTML for the application to handle. See <<markdown>>.

== Xml

`Xml.parse_str(source, {})` returns raw XML names, a declaration and a root.
Use `Xml.Namespaced.parse_str(source, {})` when expanded namespace identities
matter. Both support `limits: Bounded(readerProps)` for untrusted documents,
pull readers and chunk decoders. Readers expose `{ location, declaration }`
through `reader.metadata()`. Namespace-resolved documents provide
`document.encode(writeProps)`. See <<xml>>.

`Html`, `Svg` and `MathML` return shared `Markup.Source` and `Markup.Tree`
values. Use `source.position(offset)`, `tree.single_root()` and `tree.text(root)`.
`Markup.Name` carries explicit namespace, local and prefix identity and offers
vocabulary queries as receiver methods. `Markup.Context` checks authored
placement; `Html.RepairContext` checks HTML repair semantics. Template plans
live under `Markup.Template`, expose read-only metadata and bind with
`plan.bind(values.iter())`. See the markup chapters for those distinct tasks.

== Yaml

`Yaml.parse_str(source, {})` returns a configuration tree. `Yaml.decode_str`
decodes directly into records, lists, dictionaries or tuples; optional values
use `Try(value, [Missing])`. `Yaml.value_parser(props)` offers the same typed
decoding through generic parser receivers. Native failures, including missing
required keys, use `InvalidYaml`. See <<yaml>>.

== Choosing between modules

Use <<choosing-an-approach>> to choose type-directed decoding, a document tree,
combinators or ordinary string operations. <<conformance>> records each format's
supported specification and known gaps.
