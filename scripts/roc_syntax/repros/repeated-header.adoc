= Repeated native entrypoint calls change generated text

`repeated-header.roc` is a standalone deterministic text generator reduced from
the CSV property target. Its only dependency is pinned roc-fuzz 0.4.3; it imports
no CSV parser or roc-parser package modules. This is a correctness reproduction,
separate from the ownership allocation experiment in `README.adoc`.

== Reproduce on Linux x86_64

[source,shell]
----
"$ROC" build --no-cache --opt=speed --fuzz \
  scripts/roc_syntax/repros/repeated-header.roc --output=./repeated-header
python3 -c 'from pathlib import Path; Path("one-byte").write_bytes(bytes([1]))'
./repeated-header one-byte -runs=1
./repeated-header one-byte one-byte -runs=1
----

The first invocation succeeds. In the second invocation the first input
succeeds, then the second identical input fails the nonempty-header property
and exits 77. These raw libFuzzer file arguments invoke the same generated
native entrypoint twice in one process; this does not require random mutation
or a retained corpus. Running the one-input command repeatedly as separate
processes does not reproduce the failure.

The expected header is `id,score,name`. On the second call it becomes empty,
while the two generated data rows remain. `show one-byte` in a fresh process
confirms the expected initial header. All checks remain enabled.

== Verified configurations and limits

The final identical source was rebuilt without caches using:

* `nightly-2026-10-15-38e6c42`
  (`38e6c42c889cc7ffd97beea9199186790cc848f5`), Linux x86_64 compiler;
* immutable compiler main `0d4b0ab02f9239448d034db17b4e63051a7c57ae`,
  built with Zig 0.17.0 and `-Doptimize=ReleaseFast`, identifying as
  `research-main-0d4b0ab`, cross-compiling with `--target=x64musl`.

Both emitted x64musl executables reproduce the same one-call success/two-call
failure in Linux x86_64 containers on macOS arm64. The original full CSV target
also failed on native GitHub `ubuntu-latest`; this standalone reduction has not
separately been run on native x86_64 hardware. The same isolated source has not
been checked on other backends or architectures.

`repeated-header-observed.json` retains final source and executable hashes,
compiler revisions, controls, input bytes and observed output. It contains no
machine-specific filesystem paths.

The responsible compiler/runtime pass has not been established, and a platform
interaction has not been ruled out. Smaller isolated map/join and list-append
examples passed, so the report retains the wider generator that actually
reproduces the difference rather than claiming an unverified minimal cause.
